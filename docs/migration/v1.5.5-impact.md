# Bannerlord v1.5.5: impact on TAOM

**Date:** 2026-10-09 · **Branch:** `chore/engine-bump-v1.5.5` (from `bannerlord-1.5.x` `d1b9fd91a`) ·
**Engine:** client and Modding Kit v1.5.5.124170 (`package_info.txt` "Compile Changeset: 124170",
asset changeset 124076), Steam beta, buildid 25822820; client stamped 07:14, Modding Kit 06:03 ·
**Predecessor:** [v1.5.4-impact.md](v1.5.4-impact.md) ·
**Issue:** to be filed (links #736).

## Bottom line

- **A fresh build needs no code change, and the released testing build v2.0.34 still runs.**
  `dotnet build TAOM.Tests --no-incremental` against the installed v1.5.5 assemblies: 0 errors.
  `tools/check_engine_member_refs.ps1` over every shipped DLL that references the engine (TAOM.dll,
  `DualWield_TAOM`, `TAOM.Dependencies`, every ButterLib and MBOptionScreen implementation, MCMv5,
  UIExtenderEx), with the v1.5.4 BUTR reference assemblies as the baseline: 0 new misses. The
  testing v2.0.34 `TAOM.dll` resolves all 4,046 of its engine references (member references, now
  including those on generic types, plus type references; the first pass, members only, counted
  3,028); a fresh build of HEAD resolved 3,041 of 3,041 member references. UIExtenderEx keeps one miss, `ViewModel.OnPropertyChangedWithValue(Object,String)`,
  which v1.5.4 also lacks (pre-existing). A positive control (the v1.4.8-line build) shows 13 misses.
- **Every binding still resolves.** Strict binding gate on HEAD: 494 passed, 0 failed, 0 skipped
  (it also runs `XmlMergeLiveEquivalenceTests`). A read-only metadata pass found all 295 Harmony
  targets (294 rows, the 27 generic-arity rows included), 144 GameModel override signatures on 53
  models and 74 reflection sites unchanged, no new abstract or interface member on any type TAOM
  derives from, and no change to the 113 engine enums TAOM compiles in except
  `SpectatorCameraTypes` (`OrbitAroundTarget` removed; TAOM uses `LockToMainPlayer`, still 1).
- **One TAOM.Dependencies change: `SubModuleConstructionGuard` is deleted.** It never protected
  anything. On v1.5.5 the only `MBSubModuleBase` constructor is 7 bytes (`ldarg.0; call
  object::.ctor; ret`) with no fields, and C# runs a derived SubModule's field initialisers before
  the base call, so there was no base-constructor exception left to swallow. Its `Install()` also ran
  from `OnSubModuleLoad`, after `Module.LoadSubModules` had constructed every SubModule (true on
  v1.5.4 too: 526 installs since 2026-05-27, 0 logged swallows). v1.5.5 `Module.AddSubModule` catches
  any constructor exception itself and returns `CriticalError`; `LoadSubModules` then shows a message
  box naming the module, calls `MBDebug.AbortGame` and throws. Players lose nothing. `CoopPresence.cs` and
  `dr3-maintenance.md` describe the new behaviour; `bannerlord-together-compat.md` row 295 still
  describes the guard (owed, below).
- **Players inherit six vanilla fixes**; no TAOM patch or full-replacement model blocks one (read
  from the v1.5.5 decompile against the archived v1.5.4 one):
  - after a village raid, weak lord parties no longer attack the raiding army
    (`MobilePartyAi.GetNearbyPartyDataWhileDefendingSettlement` now reads the last attacker's strength);
  - a peacetime raid applies the crime rating before the Honor and Mercy trait XP
    (`BeHostileAction.ApplyGeneralConsequencesOnPeace`, a reorder; BannerlordCoop's transpiler on it
    still finds its single `OnHostileAction` call);
  - the ransom broker's blood-feud options work with several feud clans (`ExecutionCampaignBehavior`
    builds the clan list on the player line; TAOM's two Execution patches target unchanged methods);
  - incidents no longer delete captive lords (`CampaignIncidentEffects.RemovePrisonersRandomlyWithPredicate`
    is renamed `RemovePrisonerTroopsRandomlyWithPredicate` and skips heroes; TAOM calls neither);
  - bandit voice-over plays (`DefaultVoiceOverModel` accepts `/` in voice paths and untagged paths).
    TAOM has no voice-over model, so more vanilla Calradian lines will probably play on TAOM lords
    and bandits. Not yet heard in game;
  - saves written before v1.5.3.123225 stop a party not at war with the player from engaging
    the player (`MobileParty.AfterLoad` migration only).
  Unlisted: `TraitLevelingHelper.UpdateTraitXPAccordingToTraitLevels` now also resets level-0
  traits, and `Formation.Reset` resets `RepresentativeClass` (`BattleActionBarVM.cs:92` reads it).

## What moved

- **Public API**, v1.5.4 BUTR reference assemblies against the install: 14 of 72 assemblies
  changed. Most of it is the multiplayer spectator-to-streamer rework (`MultiplayerOptions.OptionType`
  renumbered, spectator members and four network message types removed). Outside multiplayer:
  `DoubleStringBasedVisibilityWidget` removed, `MissionScreen.SetSpectatorCameraOverride` and
  `IsRightButtonDragging` removed, `ViewCreator.CreateMissionReplayView` removed, the incident
  method rename above, and a new `IHttpDriver.HttpSendAsync` interface member. TAOM references none.
- **Native:** `TaleWorlds.Native.dll` grew 3,072 bytes. The engine-method map is 687 MountAndBlade
  (one fewer), 1,562 Engine (one more) and 33 DotNet methods, with no map warning on either binary.
  Every per-build address moved; the new rows are in the three pin tables (below).
- **Vanilla data:** Native `consoles.xml`, `module_strings.xml` and `native_strings.xml` changed; no
  XML schema changed. All 78 ids that `module_strings.xslt` drops still exist. Every Native asset
  package was re-packed (asset changeset 124076), as were 338 SandBox and SandBoxCore scene objects.
- **Vanilla GUI:** 8 Native and 2 SandBox files changed. TAOM's `PartyNameplateItem.xml` clone
  differs from the v1.5.5 file only by TAOM's own edits, and the `AgentStatus` prefab extension
  (`CareerEnergyBarPrefab.cs`) keeps its XPath anchor, constants and brushes.
- **Hand-copied engine ids:** the 32 policy ids and 16 code-registered item ids are unchanged.

## Member-level body diff

`tools/engine_body_diff.py --old-suffix _v1.5.4`, on the snapshot after merging trunk (2026-10-14):
543 bound members (297 patch-target rows, 152 GameModel override rows, 86 reflection rows and the
`Deserialize` loaders), 0 unparsed, **543 identical, 0 changed, 0 unresolved**. Two rows resolve through inheritance
(`GetDetachmentCostMultiplierOfAgent`, declared on `AgentStatCalculateModel`). Every v1.5.5 change
the release notes describe sits in a method TAOM does not bind. Calibration: the same tool on
v1.5.3 to v1.5.4 still reports the 8 known changes (the 7 in `v1.5.4-impact.md` plus an assert line
number in `Kingdom.Deserialize`), so the zero is not a blind spot.

The first run reported 509 changed. The cause was the installed Coop module, which ships 40 v1.5.4
`TaleWorlds`/`SandBox` DLLs of its own: `decompile_bannerlord.ps1` decompiles every module's bin, so
the new `_modules_build` held a second, stale copy of every engine type. The tool now reads engine
assemblies only from vanilla modules (`test_third_party_engine_copy_is_ignored`).
