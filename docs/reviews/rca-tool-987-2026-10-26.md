# RCA: audit and lint tool items #987 (deep-review, 2026-10-26)

## Top-line

Issue #987 held seven items deferred from the #983/#984 review: the `project.mbproj` audit's exact requested-id list,
an exit code for "nothing audited", engine-like decoding, the repo copy of TAOM's manifest, the dash scanner's fence
walker, a mistyped `--dash-base`, and the commit hook's handling of `--amend` and path commits. `/deep-review` ran in two
waves (Standards, Engine, Data flow, Tooling; then Efficiency, Completeness, Design, with a convergence pass; three of the
second wave stopped at the session limit and were resumed). Three HIGH findings, all fixed before the commit:

- **The new commit reader opened a bypass on the commonest commit shape.** To judge a path commit, the hook asked the
  shell-word reader for the paths after `git commit`. The reader took `2>&1` as the three paths `2`, `>&`, `1`; the hook
  found no relevant file among them and allowed the commit without running the linter. Half the commit calls in recent
  transcripts end in a redirection. The base hook denied all of them.
- **INERT-ROW was a new exemption wider than the case it was written for.** Any `<XmlName>` that registered the same file
  turned a dead `project.mbproj` row into a "harmless" warning, whatever the id or the row type, so a spider-class
  `action_set` row beside a SubModule registration passed with exit 0.
- **A path commit typed from a subdirectory was not judged.** The reader returned paths relative to the call's
  directory; the hook resolved them from the top level, found nothing and allowed.

## Root-cause pattern: a reader proven on the shapes in the brief

Findings 1, 3 and 9 are one class. The commit reader was built from the shapes the brief listed (`--amend`, `-- paths`,
paths after the message) and tested on exactly those. Real commands carry redirections, subdirectories and wrappers,
and the repo already holds the lesson for this (#985: test rows include a wrapped form and a grammar form). What made it
a bypass, not a miss, is the direction of the new code: before #987 the hook judged the index for every commit, so a
misread command could not shrink what it checked; after it, any misread path list narrowed the check to nothing. Finding
2 is the same shape in the audit: a new exemption written from the brief's example (the Armory's four rows) instead of
from the engine's condition for a load.

**Preventive action.** A change that makes a gate check LESS based on a parsed reading (a narrower path set, a
downgrade) keeps a fallback to the old check when the reading resolves nothing, and is replayed on real inputs (the
local transcripts, the live install) before review.

## Convergence

The convergence pass re-ran every wave-1 finding against the base hook in a sandbox: 37 redirect forms, 20
subdirectory forms, the audit's exact-id cases, the live install and the spider-era replay. H1 to H3 and M1 to M4 were
fixed; it found finding 9 (`>|`, abbreviated options) and the wrapped-amend regression in finding 11, both fixed in the
second fix round with tests.

After the second round: the four changed test modules ran 540 tests OK; the live audit reports 0 errors and 5 warnings
(four INERT-ROW, one MERGE-RISK), rc 0; `lint_docs.py --fail-on-drift` exits 0 with `ai_dashes` 0 and `git_diff_failed`
0. The H1 mutation is killed by the unit tests, not at hook level: there the fallback to the index masks it, which is the
fallback's purpose.
